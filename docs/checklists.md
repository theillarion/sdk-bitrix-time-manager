# Чек-листы Python SDK и CLI

Дата: **8 октября 2026 года**. Версия: **0.1.0**.
Связанные документы: [требования](technical-requirements.md),
[сценарии](use-cases.md), [ограничения](limitations.md).

Чек-листы используются при изменениях, интеграции и выпуске. Флажки заполняются
для конкретной проверки с версией/коммитом, окружением и результатом. Пункт
матрицы со ссылкой на тест означает наличие теста, а не его запуск в этом документе.
Список будущих тестов не является отчётом о реализованном покрытии.

## CHK-01. Изменение SDK и CLI

Связь: TR-01–TR-18, NFR-01, NFR-04, NFR-05.

- [ ] Проверены публичные импорты, сигнатуры и DTO; изменения отражены в документации.
- [ ] Основные функции доступны прямым Python-вызовом без дополнительного сервера.
- [ ] Входы валидируются до добавления; лишние поля и недопустимые интервалы отклоняются.
- [ ] Preview не вызывает добавление и не создаёт журнал.
- [ ] Реальная запись требует явного разрешения; CLI требует `--apply`.
- [ ] До внешней записи сохраняется резервация; повторов `crm.item.add` в транспорте нет.
- [ ] Проверены повтор операции, изменение caller key, ручной дубль и конфликт.
- [ ] Потеря ответа и отмена не превращаются в подтверждённое отсутствие записи.
- [ ] Изменение ID операции/зоны/схемы журнала не обходит защиту старых операций.
- [ ] Изменения API сопровождаются необходимыми тестами и описанием совместимости.
- [ ] В примерах и Git отсутствуют рабочие секреты, `.env`, журнал и резервные копии.
- [ ] Пройдены статические проверки и применимые тесты; сохранены результаты.

Команды для текущего контура SDK и CLI из корня проекта:

```bash
python -m pip install -e '.[dev]'
python -m pytest -q tests/test_models.py tests/test_client.py tests/test_service.py tests/test_cli.py
ruff check .
ruff format --check .
mypy src
python -m pip check
```

Команды установки могут обращаться в реестр пакетов. Тесты SDK и CLI должны
работать с `httpx.MockTransport` и временными файлами, без реального Bitrix.
Этот документ не фиксирует достижение процента покрытия.

## CHK-03. Интеграция с приложением

Связь: TR-02, TR-03, TR-18, NFR-02, NFR-03; UC-14.

- [ ] SDK подключён как зависимость с определённой версией/коммитом.
- [ ] Вызываются публичные методы `TimeManager`, а не приватные функции.
- [ ] На подключение создаются свои `Settings` и клиент; общая среда не подменяется `.env` разных людей.
- [ ] URL/вебхук берутся из проверенного подключения, а не произвольного callback.
- [ ] Для пользовательских URL реализована необходимая приложению защита SSRF.
- [ ] Перед записью проверяются пользователь, допуск, дата и разрешённое действие.
- [ ] Сохранены параметры, зона и key запуска; повтор использует тот же контекст.
- [ ] Задан общий абсолютный путь журнала для исполнителей одной операции.
- [ ] Разные операции одного сотрудника сериализуются в приложении с учётом LIM-01.
- [ ] Для бота запрещено создание рабочего дня и произвольные вызовы низкоуровневого клиента.
- [ ] `preview`, `created`, `existing`, конфликт и неопределённый результат отображаются различимо.
- [ ] Известный успех не стирается из-за ошибки отправки уведомления приложения.
- [ ] Клиент закрывается при завершении, новые записи при остановке не запускаются.
- [ ] Секреты и рабочие тексты защищены в БД, файлах, логах и резервных копиях приложения.

## CHK-04. Потеря ответа, отмена и ручное освобождение

Связь: TR-13–TR-15; UC-09–UC-13.

- [ ] Записан ID проблемной операции, сохранены исходные данные и контекст.
- [ ] Проверен исправный журнал; операция не объявлена неисполненной по отсутствию ответа.
- [ ] Выполнена сверка с Bitrix через повтор исходного вызова; добавление не отправлено вслепую.
- [ ] Найденная подходящая карточка перевела журнал в `succeeded`.
- [ ] Если карточка не найдена, pending/uncertain осталась заблокированной.
- [ ] Перед `resolve` оператор проверил отсутствие карточки и незавершённого отправителя.
- [ ] `resolve` применяется только к pending/uncertain и не отправляет запрос создания.
- [ ] Повтор после освобождения — отдельное явное действие с актуальными правами приложения.
- [ ] Успешная, но удалённая вручную карточка не пересоздаётся за счёт очистки журнала.
- [ ] Отмена во время добавления сохраняет неопределённость и `CancelledError`.
- [ ] Отмена проверочного чтения после сохранённого ID не стирает `succeeded`.

## CHK-05. Ручная сверка поддерживаемого портала

Связь: TR-04, TR-10–TR-12, LIM-05.

Проверка портала выполняется отдельно от автоматических тестов. Сначала только
чтение. Запись — лишь для конкретной выбранной операции с явным разрешением
оператора и понятными датой, данными и ожидаемым результатом.

- [ ] Прочитан профиль и подтверждён ID владельца вебхука.
- [ ] Сверены типы, категории, пользовательские поля, виды дня и справочник минут.
- [ ] Подтверждены права владельца на нужные операции; нет попытки обхода отказа.
- [ ] Найден собственный существующий день и проверена связь учета с ним.
- [ ] Выбран доступный договор и сверена кодировка CRM-ссылки.
- [ ] Прочитана выбранная удалёнка и её связь с днём, если связь появилась.
- [ ] Preview не привёл к записи и показал ожидаемые поля.
- [ ] Для разрешённой ручной записи сверены ID, поля, ссылка и отсутствие дубля.
- [ ] Изменения роботами зафиксированы как наблюдение с датой, а не универсальная гарантия SDK.
- [ ] Не создавались запрещённые карточки для проверки границ без отдельного решения оператора.
- [ ] Результат отделяет чтение, preview, реальную запись и неизвестные факты.

## CHK-06. Журнал, перенос и окружение

Связь: TR-03, TR-14, NFR-02, NFR-03; UC-11, UC-12.

- [ ] Журнал доступен по одному абсолютному пути, права файлов настроены.
- [ ] Оценены конфликты SQLite при `timeout=0`; ошибка занятости не обходит резервацию.
- [ ] Для копирования остановлены исполнители либо используется согласованный снимок SQLite.
- [ ] Перенесены весь журнал, настройки подключения и необходимые секреты.
- [ ] Старый и новый экземпляры не пишут одновременно с независимыми копиями журнала.
- [ ] Pending/uncertain после переноса сверяются; succeeded и привязки caller key сохранены.
- [ ] Новая зона хоста не меняет заданную зону SDK; рабочий каталог не подменяет путь БД.
- [ ] Виртуальное окружение создано заново, импорты/CLI указывают на новый checkout.
- [ ] Потерянная/неисправная БД рассматривается как требующая сверки, а не разрешение повторить всё.

Это проверки локального состояния SDK. Полный перенос пользователей,
расписаний и ключей шифрования бота описывается в проекте приложения.

## CHK-08. Проверки, которые ещё нужно добавить или расширить

Связь: LIM-01–LIM-10. Эти пункты **не заявлены как выполненные тесты**.

- [ ] Разные пересекающиеся интервалы одновременно с одним журналом; исключение второго добавления после исправления LIM-01.
- [ ] Разные запросы создания дня одной даты одновременно.
- [ ] Одинаковая операция из отдельных процессов с общим журналом.
- [ ] Отказ/занятость/повреждение SQLite до отправки, после ответа и при фиксации результата.
- [ ] Повреждённые поля метаданных, числовые значения, связи и ID; понятные безопасные исключения.
- [ ] DST gap/fold, эквивалентные моменты с разными смещениями и смена зоны между повторами.
- [ ] Курсоры неверного типа, несколько страниц, достижение limit и большие выборки.
- [ ] HTTP 429/5xx, `QUERY_LIMIT_EXCEEDED`, не-JSON, неподходящие result и отсутствие повтора добавления.
- [ ] Caller key на границах длины, preview без привязки, изоляция по порталу/владельцу.
- [ ] CLI ошибки argparse, `journal`, `resolve`, коды завершения и прерывание.
- [ ] Установка базового wheel в чистом окружении и выбранная матрица Python.
- [ ] Маскировка секретов в используемых приложением обработчиках логов и traceback.
- [ ] Минимизация/сроки хранения и формат нового журнала, если эти улучшения приняты.
